# 从检查错误到构造可行候选

新增通用 `resimind.search`，以及出游领域的时间窗口传播、路线选择、过夜构造和有限餐厅重选。**默认保守策略仍为 0/2 来源任务完成；明确标注两处可选酒店访问后，苏州任务可以完成，重庆仍需重新翻译约束。** 本轮没有新增模型调用，也没有新的未见测试成绩。

## 实际结果与人工介入

输入是上一轮全部 **5 个非空候选，来自 2 道已经用于开发的任务**，先经过已公开的字段修复。苏州占 3 个候选，其中第 2、3 个相同；重庆占 2 个。不能把它们当成 5 个独立任务。

| 处理方式 | 官方完整通过的候选 | 可交付来源任务 | 新模型调用 |
| --- | ---: | ---: | ---: |
| 先前仅字段修复的草稿 | 0/5 | 0/2 | 0 |
| 新搜索，默认保留所有语义不明活动 | 0/5 | 0/2 | 0 |
| 新搜索，显式标注两处可选访问 | **3/5** | **1/2** | 0 |

第三行包含人工语义标注。苏州模型候选把首日早晨与末日下午的酒店访问写成 `rooms=0`，像是寄存行李，当前 schema 没有相应活动类型。阅读公开原题后，将这两处确定为未被用户要求的模型建议，逐候选指定 `[day_index, activity_index]` 为 `[[0,1],[2,4]]`，允许省略。每份输入及授权都在运行前冻结。**没有声称寄存行李已经完成，也没有把这一判断算成自动模型能力。** 缺少可信应用明确标注时，系统保留活动并不交付；内容完全重复、无法唯一定位的授权也会被拒绝。

苏州 3 个候选均在 3 次展开、11 个候选生成计数、7 个唯一候选校验后交付，最终收敛为同一份计划，不是 3 个独立成功。重庆在约束预检阶段停止，没有为了取得分数而改写原约束。按候选原有顺序选择第一个本地接受结果，之后才评分，不按 gold 挑选最佳候选。

## 这次增强解决了什么

- 原计划将 13:00 的参观排在 11:35 午餐之前，酒店过夜又排在晚餐之前。新候选重新安排先后，保留全部景点及往返车次，并在每个非末日末尾显式回到酒店、结束于 `24:00`。
- 路线、票价、营业时间和建议最低游玩时长均来自官方沙盒。每次换时间或餐厅都会重新构造路线，再跑完整检查；不靠挪动单个字段制造通过。
- 荣阳楼 17:30 关门，旧计划却安排 17:30–18:30 晚餐。在允许重新选择未被用户点名的餐厅后，候选换成目录中的山塘书香府邸·陶然轩，安排 17:00–18:00，重新核对前后路线与价格。
- 通用搜索允许暂时退步的中间草稿，但只有全部检查为真才能交付；保留景点、城际 ID、用户点名实体、酒店选择及原任务元数据的义务独立存在。

这不是消融实验。构造器、约束预检、人工语义标注和搜索共同参与，不能将改善全部归因于搜索算法或神经符号机制。

## 重庆为什么仍未解决

模型自译 DSL 将**全部活动**的市内交通类型收集成集合，再要求它只能包含 `taxi`。官方函数对空路线返回 `empty`，而正确首程城际交通没有前置市内路线，因此该约束与适配器的首程规则冲突。新增 AST 预检只识别可证明的完整模式；返回 `needs_retranslation`，保留原文，不私自过滤 `empty` 或伪造一段出租车。

重庆还存在独立出租车活动、预算和房型选择问题。本轮未实现自动重新翻译、出租车层级转换或预算驱动的航班／酒店重选，因此没有宣称重庆已经能求解。

同时修正了我们自己的检查假设：酒店表的 `numbed` 是床数，不能直接当可住人数。现在只检查正整数房间／床数、官方房型事实和自译房型约束，不用床数乘房间数来证明容量。**数据中没有实际入住上限，这一项没有得到验证。** 历史结果与源码快照保留，未用新规则重写旧记录。

公开[精简结果、源码哈希和显式标注](evidence/chinatravel-search-v1/summary.json)、[复现说明](../experiments/chinatravel_search/README.md)、测试代码及一个可运行的[通用示例](../examples/bounded_search.py)。本轮完整候选、工具结果、诊断与源码快照保存在本地，没有新增大包测试日志到 GitHub。摘要的哈希用于识别对应字节，不单独构成独立审计证明；需要验证结果时，应使用公开输入和脚本重新运行。

生成进程只能读取公开原题、旧候选、自译约束、代码与沙盒数据；不能读取 gold。全部输出结束并固定哈希后，父进程才导入评分器、读取 gold。两种策略在同一版本上分别运行，未挑选替换失败候选。

本轮通过只指固定的 ChinaTravel 沙盒与编码约束。苏州“轻快、不要特种兵”等软偏好没有被完整形式化；交通时间沿用官方模型（包含分钟取整），不代表真实路况或可直接预订的行程。没有得到未见任务、国际排名或端到端自主完成率的提升证据。

下一阶段应解决自然语言到约束的误译与活动语义表达，再冻结版本运行未用于开发的任务。继续增加同一批旧题的测试记录不能替代这一步。
