# ResiMind 前沿研究目标与验收条件

目标是一套由残差诊断驱动、能够验证结果和持续积累能力的 Agent 架构。
“达到前沿”是需要外部证据支持的研究结论，不能作为发布版本的自我认证。
本文件把完整目标固定下来，避免把新增模块、通过率提高或演示成功混为一谈。

## 当前已实现且经过测试的部分

- 依赖图能跟踪未完成工作，输入或上游结果变化后使下游结果失效；桥梁适配器实际使用了局部重算。
- 数学搜索保留有限备选行动，具有共享的调用预算、独立验证和可选 Lean 证明检查。
- 共享子表达式与稀疏结果解决了原先两道长表达式压力题；输入语法和输出证书分别保持资源边界。
- 成功推导可以进入跨任务历史，抽取并验证通用多项式规则，再经结构检索用于新的系数组合。
- 训练、冻结、保存、重载和撤销有明确接口；评估期间不会自动吸收测试答案。
- 经验策略能够学习选择规则、紧凑计算或搜索；失败反馈有明确类别，但还不是学习得到的因果诊断。
- 240 道生成题和组件消融已完成。结果表明主要收益来自更合适的计算工具，未证明知识增长提高了能力上限。

具体实验、限制与复现方法见 [实现与结果](lifelong-math.md)。

v0.13.0 之后的[本地一般目标试验](formal-memory-pilot.zh-CN.md)进一步覆盖了
命题逻辑、自然数关系和固定归纳配方，完成四轮定理记忆对照。直接复用随记忆
增长，但三组完成率均为 24/24，尚无完成率或稳定成本增益。这不更新外部排名，
也不把四轮重复探针视为长期知识增长证据。

当前开发版又加入了[条件引理的残差组合](formal-composition-pilot.zh-CN.md)：
规划器能在有界深度内引入条件、应用多条已核验引理并回填局部假设，完整计划
再交给 Lean 编译。它补上了“只能整条目标回忆”的工程缺口；开发链的成功不等于
强 `grind` 或外部定理证明系统的性能提升，组合收益仍需冻结题集和同工具预算验证。

验证记忆现在还提供了[可审计的生命周期元数据](verified-memory-lifecycle.zh-CN.md)：
来源任务、证据引用、适用标签、过期时间和核验器版本随记录保存；过期规则不会被
检索，重载仍由 Lean 重新核验，并可输出跨题迁移统计。这些接口改善了长期维护和
审计边界，但不把一次回忆自动解释成迁移因果或前沿基准成绩。

## 完整研究工程的八项验收目标

| 目标 | 必须交付的实现 | 必须提供的证据 | 当前状态 |
| --- | --- | --- | --- |
| 统一任务与证据表示 | 类型明确的目标、条件、来源、证据等级和依赖关系；领域语义由适配器负责 | 在数学、工程和开放任务中，共同内核执行一致的状态与失效规则 | 已有基础，领域接口尚未全面统一 |
| 紧凑可复用的推理表示 | 共享计算、惰性展开、带依据的等价变换和结果证书 | 同等问题下降低空间与计算开销，资源耗尽时不错误宣告完成 | 有界多项式已实现；通用证明表示未完成 |
| 残差诊断驱动决策 | 区分证明、条件、信息、计算和模型缺口；选择针对性修复 | 与只接收成功/失败信号的方案做消融，节省真实预算或提高完成率 | 已有反馈分类与依赖失效；尚无普遍收益证据 |
| 可学习的搜索控制 | 状态特征、行动价值、分解策略、工具成本与停止条件 | 固定底座模型和总预算，对比固定策略、强搜索和验证重试 | 有经验排序和多路线搜索；尚未完成强基线研究 |
| 有条件的知识形成与组合 | 引理、规则、程序片段及其适用条件；支持组合与安全实例化 | 对未参与训练的新结构任务有增益；错误条件不能被消去 | 已有有界条件引理组合和 Lean 重编译；一般引理学习、跨题增益尚未证明 |
| 长期知识维护 | 去重、检索、淘汰、版本、撤销传播、来源和依赖记录 | 长任务序列中库增长仍可控，不因错误知识扩散或旧任务退化而失效 | 有界存储、检索、重验与撤销已实现；长期试验未完成 |
| 多层验证与跨域迁移 | 严格区分形式证明、精确计算、误差界、实验支持和未知 | 迁移的是经过核验的方法与接口，不能把一个领域的结论无条件搬到另一个领域 | 数学与桥梁各有独立检查；一般跨域迁移未证明 |
| 自主课程与持续改进 | 依据薄弱能力生成训练任务、获取反馈、回放旧任务、验收更新 | 冻结评估集，展示多轮学习曲线、迁移收益和无退化检查，计入全部训练成本 | 当前课程由人设定；自主课程未实现 |

## 实验协议必须满足的条件

先固定评估问题、模型、提示、工具权限和资源预算，再执行比较。训练和开发
材料与最终测试分开；变量改名、系数变化、结构组合变化及新数学领域要分别
标注，不能统称为未知任务泛化。

同一个底座模型至少对照直接回答、验证反馈重试、强搜索、领域成熟工具及
完整 Agent。工具集必须一致；新增强工具的收益应通过“只有该工具”的基线
单独报告，不能全部归因于 Agent 架构。

必须同时报告完成率、错误接受、拒答/未知、模型调用、token、真实运行时间、
训练和验证开销、规则库规模、知识维护成本。超时、解析失败和外部服务错误
保留在结果中。不同预算单位不可互换；控制计算预算需要实际可执行的资源
约束，而不只是把不同系统的“步数”都设成同一个数。

多轮知识增长实验同时评估新任务、旧任务和新组合任务。新规则进入测试前
先完成准入和冻结；撤销规则后检查依赖结果是否正确失效。对确定性任务做
独立校验，对随机模型重复试验并报告配对不确定性，不能只展示最好的一次。

一般形式证明需要公开、合法取得、未用于提示调试的正式题集，并固定 Lean
与依赖版本。当前的多项式展开通过率不能换算成 MiniF2F 等证明题的通过率。
工程则要明确模型假设、输入来源、校准与适用范围，计算器间一致不等于现实
结构已经通过安全或规范审查。

## 可以形成研究贡献的主张

真正需要被证实的主张是：**残差诊断使系统选择更有效的行动；被验证的抽象
提高新任务上的能力或降低成本；知识增长与策略更新相互促进且不破坏可靠性。**

这些主张尚未全部成立。当前完成的是其中若干基础实现与范围有限的对照。
只有在强基线、未参与开发的任务、长期序列和独立复现中仍成立，才有根据把
该架构称为相关方向的前沿成果。该标准不能用模块数量或主观百分制评分替代。
