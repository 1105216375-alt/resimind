## 开放性与独立检查

验证器不与固定标准行程比较。提交的 92 项领域测试包含同一请求下三个不同的有效行程，覆盖不同地点组合、顺序与交通方式。独立只读评审另构造 384 个候选，199 个被接受，涵盖 17 种地点顺序；这些探索性检查不计入 660 项测试数，也不是模型性能数据。

核验范围包括三处以上不同场所、艺术与用餐类别、开放窗口、最短停留、逐段交通与完整返程、预算、步行上限和雨天室内场所要求。测试覆盖返程单独导致超预算、未选交通数据缺失不影响有效方案、所选交通数据未知必须延后、类型混淆、伪造金额与时间、错引用、篡改快照与事实、主观说明混入已验证输出等情形。

| 离线场景 | 实际结果 |
| --- | --- |
| 普通出游 | 50 分钟步行超过 45 分钟上限，拒绝且保持状态不变；修改交通后为 22 分钟、61 元，13:38 返回 |
| 雨天 | 花园不满足室内要求，拒绝；修正为室内场所后通过 |
| 缺返程数据 | 保留 `trip:transport_grounding` 等未决义务，不生成已核验行程 |

“轻松”“有趣”等主观理由不进入正式事实。通过表示满足给定数据下的明确约束，不表示最优、最受欢迎或真实场所可预订。

## 三次真实规划实验

完整原始提议、反馈、设置、调用量和复现方式见[开放式规划实测](evidence/open-planning/README.md)。每次新增 API 响应均标识为 `deepseek-flash`。

| 实验 | 新模型调用 | 验证结果 |
| --- | ---: | --- |
| 普通出游 | 1 | 第一次通过：58 元、步行 32 分钟、13:05 返回 |
| 雨天室内 | 1 | 第一次通过：65 元、步行 8 分钟、12:59 返回 |
| 咖啡改为必选 | 1 | 先重检并拒绝实际旧候选，再由模型基于反馈改成新组合：73 元、步行 35 分钟、13:04 返回 |

第三次实验把第一份真实候选作为初始输入，修改明确的必需类别；旧方案在旧条件下本来有效，在新条件下缺少咖啡。共有两次提议评估，但只新增一次 API 调用。未把复用候选算成新调用，也未把前两次成功伪装成模型纠错。三次 smoke 实验不能建立准确率、比较优势或用户体验指标。

包括此前数学与客服的全部七份联网记录均使用发布版独立验证器离线重放，完整事实、轨迹、残差、证据与停止原因一致。重放验证决策一致性，不提供第三方来源认证。没有新增真实 OpenAI 请求。

## 复现

```bash
python -m pip install '.[dev,deepseek,langgraph]'
python -m pytest -q -o pythonpath=.
python -m resimind demo --domain planning
python -m examples.open_planning --scenario rain --json
# 缺少交通信息，预期退出码为 1：
python -m examples.open_planning --scenario missing-travel --json
python tools/replay_live_audits.py
python tools/render_planning_demo.py
```

这里只为复现全量可选集成测试安装 LangGraph；运行独立 Agent 只需安装 ResiMind 核心。[GitHub Actions 配置](github-actions-tests.yml)仍是模板，当前未启用远程 CI。全部出游数据是合成输入，没有查询真实营业信息、天气、路况或执行预订。
