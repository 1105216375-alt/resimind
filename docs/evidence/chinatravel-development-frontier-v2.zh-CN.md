# ChinaTravel 残差预算分配开发复跑

这是在 2026-10-15 对 ResiMind ChinaTravel 适配器做的**开发样本复跑**，不是完整
154 题结果，也不是外部榜单成绩。目标是验证一个工程修复：把同一个 ReAct 原生
步数上限固定为 60，其中 ResiMind 初始搜索最多 40 步，剩余 20 步只能用于收到
验收残差后的连续修订；官方 ReAct 也使用 60 步上限。模型、请求、总 token、墙钟
和 sandbox 上限保持共享。

## 冻结信息

- 题目：保留的两个 development UID，共 6 个 arm/task 运行。
- manifest：`a08bf4c2702df36a5c16c2d1c5c619a39416fee0b3cd94f60bd0b1040bd7e196`
- 模型：`deepseek-flash`，temperature `0`，reasoning `none`。
- 主要上限：每题 128 次请求、累计输入 16 MB、累计输出 65,536 tokens、600 秒。
- ResiMind：最多 3 个完整计划候选；拒绝候选不交付，步数耗尽显式 abstain。

## 结果

| arm | 最终通过 | 交付 | 技术失败 | 预算耗尽 | 平均秒 | API 请求 | 输入 tokens | 输出 tokens |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| official_react | 0/2 | 1/2 | 1 | 0 | 87.6 | 148 | 3,694,178 | 19,771 |
| official_nesy | 1/2 | 1/2 | 0 | 1 | 130.1 | 149 | 80,740 | 20,392 |
| resimind_react | 0/2 | 0/2 | 0 | 0 | 106.4 | 150 | 3,804,397 | 34,483 |

两个 ResiMind 任务都生成了 3 个候选并经过本地检查；最终没有候选通过，所以没有
把半成品或被拒绝计划写成输出。本次运行确认了**残差反馈链确实被执行**，但
两个样本都没有获得官方通过。初始搜索没有触及预留步数边界，因此这次结果
不能单独证明 40/20 预算分配的因果收益。主要失败诊断涉及交通、时间、空间、
景点/餐厅约束和自翻译约束；拒绝输出也不能证明所有检查器都不存在误放行。

## 解释边界

这项结果记录的是修订和显式 abstention 的运行行为，不证明 ResiMind 已经
超过 ChinaTravel 的 NeSy 或其他前沿系统。下一阶段需要在冻结的正式 12 题或完整
154 题上，比较同模型的冷启动、核验热记忆和残差组合，并报告配对差值、失败类型、
调用成本与长期迁移收益。
