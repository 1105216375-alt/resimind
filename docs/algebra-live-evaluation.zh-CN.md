# 固定模型，比较 Agent 架构

ResiMind 做的是神经符号 Agent 架构。本次沿用同一个 DeepSeek 模型，比较任务控制、验证反馈和已验证知识库；没有训练新模型。

## 首轮：调用前冻结题目、代码和预算

2026-10-09，固定 `deepseek-flash`、温度 0、关闭 thinking，每题最多 8 次调用、每次最多 4,096 输出 token。先运行 2 道检查接入的题和 3 道知识发现题，再比较 8 道迁移题。题目包含分数系数、嵌套展开、三元多项式和六次幂。

| Agent 策略 | 正确完成 / 8 | 错误答案交付 | 迁移模型调用 |
|---|---:|---:|---:|
| ReAct 式动作—观察循环 | 5 | 3 | 8 |
| 整题验证后重试 | 6 | 0 | 22 |
| ResiMind 残差流程 | 6 | 0 | 22 |
| 同一流程 + 已验证知识库 | 7 | 0 | 20 |

增长组另花 **3 次模型调用**生成并入库 3 条恒等式，保存后重新验证，迁移阶段冻结。因此学习加迁移共 **23 次**，不能宣传成总调用比残差组的 22 次更少；token 也没有证明总成本下降。

本次有 **3 次真实跨题规则应用**：有通过验证的规则 ID、指纹和来源记录。检索到规则、在错误候选中引用规则，都不算成功复用。但这三题其他组也能完成；增长组额外完成的嵌套题没有成功提交规则应用。因而 **7/8 不能直接归因于规则复用**。

ReAct 式基线确实允许模型调用检查工具并读取观察，但这次模型全部选择直接提交。它是本仓库的具体基线实现，不能代表经过优化的所有 ReAct 系统。

## 根据失败改进：把“错了”变成明确系数差异

首轮有几条轨迹反复提交同一个错误多项式。旧反馈只有“精确系数不同”。现在验证器会提供一个具体差异，例如：

```text
exact polynomial coefficients differ:
monomial=x*y; lhs coefficient=12/35; rhs coefficient=0
```

这条诊断来自生产验证器。它没有生成整题答案，也没有调用最终评分器。判断通过的条件仍是所有精确系数一致；不会因为几个数值样本通过就入库。验证重试基线和 ResiMind 都能收到相同的诊断能力。

修改后，用同一批题另跑了明确标注的**已见题开发复测**：

| 策略 | 首轮完成 | 开发复测完成 | 复测迁移调用 |
|---|---:|---:|---:|
| ReAct 式 | 5/8 | 5/8 | 8 |
| 验证后重试 | 6/8 | 7/8 | 17 |
| 残差流程 | 6/8 | 6/8 | 22 |
| 残差 + 已验证知识库 | 7/8 | 7/8 | 20 |

验证重试组在一个此前失败的乘积展开题上，依据两次系数反馈用 3 次调用完成了修正。残差组与增长组的完成数没有增加：模型有时忽略差异，有时改错单项式。这说明反馈已传到模型，但如何可靠利用反馈仍需要改进。

**复测中，增长组与验证重试组同为 7/8，调用更多。**这次证据支持已实现的验证、入库和复用机制，还不足以支持“残差或知识增长全面胜出”。首轮代码、失败记录和结果保留，没有用复测覆盖。首轮源码见 Git 提交 `37bbf13`。

## 这些数字的适用范围

- 每轮只有 8 道人工构造的迁移题、一次运行；首轮调用前冻结，复测属于看过结果后的开发。没有统计显著性或国际排名结论。
- 当前代数残差是一个“仍未完全展开”的目标，加上已验证中间状态；尚未为每个未完成子项建立独立残差。
- 当前知识发现生成的是已知平方、立方、平方差恒等式，不能宣传为新数学定理发现。
- 运行时用精确有理系数比较；最终评分独立使用次数界完备网格和分数计算，覆盖完整网格才判定恒等，不是随机抽样。评分答案和采样点不反馈给模型。
- 缺失、未知、未完成和技术错误不会算成功；错误与未完成输出分别记录。无错误交付是这批测试的观测结果，不是所有任务的可靠性保证。
- API 返回的是 `deepseek-flash` 服务标识，不能据此证明后台模型版本永远不变。

两轮分别进行了 **83 / 78 次真实调用**，共报告 **72,493 / 70,606 token**，均包括接入检查和发现成本。两轮各 43 条任务轨迹均通过独立离线重放，知识库重载复核与冻结检查一致。
