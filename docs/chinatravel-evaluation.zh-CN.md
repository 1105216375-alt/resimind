# ChinaTravel 原题实测：验收有效，求解能力仍有差距

后续开发已根据本轮失败记录增加数据绑定、局部修复及任务保持提示，见[增强与开发验收](repair-development.zh-CN.md)。下面的 v1 结果和原始证据保留不变；新结果没有并入这轮正式成绩。

**当前公开版在本轮配置下：ReAct + ResiMind 完成 1/12，官方 NeSy 完成 5/12，官方 ReAct 完成 0/12。** ResiMind 这组没有错误交付，并完成一次真实修复；但另外 11 题未完成，不能把它们算成成功。这轮结果不支持“已经达到或超过先进求解系统”的宣传。

这是 **12 道官方 Human-Val 原题、三组共 36 次运行**的受控试点。全部 154 道题和完整中文沙盒均已准备，正式成绩只来自预先选定的 12 题。没有删减多日、住宿、跨城交通、人数或组合约束，也没有把原题改成单日玩具题。

## 同模型、同外部上限的结果

三组均使用 `deepseek-flash`、temperature 0、`reasoning_effort=none`。每题每组最多 128 次模型调用、单次输出 8192 tokens、累计输出 65,536 tokens、累计输入 16 MB、总墙钟 600 秒；NeSy 保留原生 `TIME_CUT=300` 搜索设置。上限相同，实际消耗不同。

| 方法 | 官方完整通过率 | 实际交付 | 错误交付 | 模型调用总数 | 每题平均调用 | 每题平均耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 官方 ReAct | **0/12（0.0%）** | 11/12 | 11/12 | 874 | 72.8 | 72.6 秒 |
| 官方 NeSy | **5/12（41.7%）** | 5/12 | 0/12 | 896 | 74.7 | 107.0 秒 |
| 官方 ReAct + ResiMind | **1/12（8.3%）** | 1/12 | 0/12 | 1,123 | 93.6 | 105.4 秒 |

“完整通过”是官方 schema、环境常识和金标准逻辑约束三项通过集合的交集；“错误交付”是已经交付但未完整通过的计划。分母始终为 12。平均耗时包含失败运行，在三任务并发的共享机器上测得，不是隔离硬件的速度排行榜。

在这 12 题上，ResiMind 接入组比 ReAct 多完成 1 题、少 11 次错误交付，调用增加 **28.5%**；比 NeSy 少完成 4 题，调用增加 **25.3%**。NeSy 的 5 道成功题包含 ResiMind 的那道成功题；另 4 题仅 NeSy 成功。不同组没有共享首轮候选，不能把组间差异全部归因于残差机制。

| 未完成原因 | ReAct | NeSy | ReAct + ResiMind |
| --- | ---: | ---: | ---: |
| 交付了未通过的计划 | 11 | 0 | 0 |
| 输出达到 8192 tokens 后截断 | 1 | 1 | 0 |
| 达到 128 次模型调用上限 | 0 | 6 | 0 |
| 验收仍未通过，三次候选额度用尽 | 0 | 0 | 6 |
| 后续没有新候选，原生 ReAct 步数已用尽 | 0 | 0 | 5 |

两次输出截断按冻结 broker 规则终止，记录为 `technical_failure`；六次调用用尽记录为 `budget_exhausted`。没有重试、补题或从失败轨迹里选一个中间计划当最终答案。此次执行的是**受控预算下的官方实现**；统一 broker 会丢弃截断响应，不等于未经限额与接口约束的论文原生运行。

## 门控究竟做到了什么

事后用金标准重新检查 ResiMind 组实际生成的 **28 个非空候选**：

- 27 个未通过官方评分的候选没有被放行：**20 个拒绝、7 个延后**。
- 唯一通过本地验收的候选也通过了官方评分。
- 本次样本没有发现“官方有效却被拒绝或延后”的候选。
- 首轮没有有效候选；**1 题通过两次修订，在第三个候选上成功**。

这支持“本轮门控拦住了无效候选，并出现一次有效修复”，不支持“完成率 100%”或“残差机制已全面验证”。这里只有一个有效候选，且门控与评分复用官方 schema／环境检查逻辑；金标准 DSL 在生成结束后才用于评分。上述一致性不是独立证明验证器无缺陷。局部验收还依赖模型自行翻译的约束，不证明完整自然语言需求都被正确形式化。

唯一成功修复的题目是 [`h20241029143546424651`](evidence/chinatravel-pilot-v1/queries/public/h20241029143546424651.json)：

| 候选 | 本地反馈与官方复查 | 结果 |
| --- | --- | --- |
| 第 1 版 | 餐馆重复、位置之间的交通衔接不合法 | 拒绝；官方不通过 |
| 第 2 版 | 仍有餐馆重复、衔接错误，还出现市内交通信息错误 | 拒绝；官方不通过 |
| 第 3 版 | schema、环境约束及金标准逻辑全部通过 | 接受并交付 |

完整计划与反馈保存在该题[原始归档](evidence/chinatravel-pilot-v1/archives/h20241029143546424651.tar.xz)；可直接浏览[最终交付](evidence/chinatravel-pilot-v1/results/h20241029143546424651/resimind_react.json)和[逐候选复查](evidence/chinatravel-pilot-v1/candidate-analysis.json)。修复发生在同一 ReAct 笔记与累计步数内，没有为每次修订重置 50 步预算。

三版候选的金标准逻辑约束原本都通过，修复针对餐馆选择、交通数据与行程连续性；不是发现并修正了漏译的自然语言逻辑。第三版更换首日晚餐餐馆，重新安排地铁／步行路线，并补上晚餐后回酒店的交通与住宿。同题 NeSy 也通过；单独 ReAct 那次运行发生输出截断，不能把它当成共享初始候选的消融对照。

## 如何据此决定下一步

**优先增强构造有效解与局部修复能力，然后做消融。** 现有流程主要让模型重写完整计划；这轮 28 个候选里只有 1 个有效。先验证“保留已核验的子计划、只修冲突部分”以及“接入构造式符号搜索”能否提高完成率，再增加其他展示场景。

更具体的瓶颈是数据与状态一致性：28/28 候选通过 schema，13/28 通过金标准逻辑，只有 1/28 通过环境检查。因此应先让交通、票价、距离和时间准确绑定工具结果，再修局部衔接；继续强化 JSON 格式帮助有限。7 次延后中，3 次来自同一题的空约束译码、4 次来自交通检查异常，也需要区分“修计划”与“修译码／检查过程”，避免拿固定的坏约束反复要求模型重写。

后续应把直接生成、只有门控、门控加普通反馈、门控加结构化残差与局部修复分开，使用共享首轮候选和可比较的后续预算，才能判断残差带来的独立收益。先在开发集修实现，新增未用过的正式题和重复运行；本轮 12 题不能在调优后继续冒充未见测试集。

这不是完整 154 题成绩，也不是国际排名。描述性 Wilson 95% 区间分别为 ReAct **0–24.2%**、NeSy **19.3–68.0%**、ResiMind 组 **1.5–35.4%**，说明小样本仍有很大不确定性；这些区间不消除固定子集、单次采样或模型服务漂移的限制。当前官方代码／数据包含 2026.08 修复，模型和预算也不同于历史论文；此前对海外 Formal Travel Planner、LLM-Modulo 等的比较仍是[文献对标](public-systems-comparison.zh-CN.md)，不是本机同场实测。数学证明和桥梁工程同样需要另用对应的可信评分器验证。
