# 经验证的知识积累：先推导，再入库，再跨题复用

ResiMind 现在提供一条实际接通的知识积累链路：Agent 完成任务后，从已提交的推导提炼候选知识；独立领域验证器决定是否入库；新任务检索知识后，仍需验证本次使用。保存的 `verified` 字段不能绕过检查，重新加载知识库会重新验证。

这一轮先验证机制是否成立。实验使用确定性的代数改写器，**没有调用神经模型，也不构成先进模型排名或数学竞赛成绩**。它证明的范围是：从实际推导自动提炼恒等式、持久化、重新验证、冻结知识库、在不同表达式中复用，并量化这些环节的代价。

## 已接通的链路

```text
题内：输入表达式 → 剩余展开目标 → 提案 → 精确验证 → 提交事实 → 重建目标
跨题：已提交的推导链 → 候选恒等式 → 证书验证 → 知识库 → 新题检索 → 再验证
```

- [`LearningAgent`](../src/resimind/learning.py) 封装现有 Agent。未完成任务不会触发蒸馏；知识入库失败不改变已经完成的任务事实。`learn=False` 禁止任务结束后新增知识。
- [`KnowledgeLibrary`](../src/resimind/knowledge.py) 按领域调用应用注册的验证器，保留通过、拒绝、未知和撤销记录。条件用于检索过滤；应用仍须证明条件在新任务中成立。此本地 JSON 存储不提供账户认证或并发写入管理。
- [`AlgebraVerifier`](../src/resimind/domains/algebra.py) 使用有理数系数的精确多项式运算，检查恒等式端点与每一步推导。它也支持带显式非零条件的消因子证书；不支持的语法或超出资源上限返回 `unknown`。
- [`polynomial_learning`](../src/resimind/domains/polynomial_learning.py) 将证明链自动变成可复用展开规则。提案器只包含通用局部代数改写，没有预写平方、立方的展开答案。规则匹配只产生候选，本次改写仍需验证。

适配器也允许通过 `build_learning_agent(..., complete=callback)` 接入真实模型提案，使用同一套状态和验证路径。下述记录使用默认离线提案器，不能用来评价该模型接口的表现。

## 发现阶段和迁移阶段

发现阶段依次输入 `(u+v)**2` 和 `(u+v)**3`。初始知识库为空，基础改写语法由开发者提供。第一题的已验证展开可以帮助第二题；最终右侧表达式取自实际提交的证明链，没有向蒸馏器传入标准答案。

发现完成后，系统保存知识库、重新加载并重新验证，记录完整文件 SHA-256。随后冻结知识库。每个迁移任务运行两组：

| 组别 | 可用知识 | 提案和验收 |
| --- | --- | --- |
| 固定库 | 相同基础改写语法，空的持久知识库 | 默认改写提案器、相同精确验证器 |
| 增长库 | 相同基础语法，加发现阶段得到的两条恒等式 | 相同提案器，优先尝试匹配规则，每次应用重新验证 |

每题两组都从空事实状态开始，共享 **64 次提案上限**。不通过调小预算制造固定库失败。迁移任务不写入知识库，每次任务之后都比较整个持久化快照，包括拒绝和未知记录，防止只检查通过规则时漏掉其他写入。

这 10 道题是公开的开发案例，表达式与发现阶段不同，但**不是未见模型测试集**。没有随机抽样、重复模型采样或显著性检验。

| 迁移任务 | 输入表达式 | 固定库提交步骤 | 增长库提交步骤 |
| --- | --- | ---: | ---: |
| 平方，正系数 | `(2*x+3*y)**2` | 4 | 1 |
| 平方，负系数 | `(-2*x+3*y)**2` | 4 | 1 |
| 平方，零系数 | `(0*x+3*y)**2` | 4 | 1 |
| 平方，重复变量 | `(x+2*x)**2` | 4 | 1 |
| 平方，嵌套替换 | `((x+y)+(z+w))**2` | 16 | 13 |
| 立方，正系数 | `(2*x+3*y)**3` | 16 | 1 |
| 立方，负系数 | `(-x+2*y)**3` | 16 | 1 |
| 立方，重复变量 | `(x+2*x)**3` | 16 | 1 |
| 不匹配的乘积控制 | `(2*x+3*y)*(x-4*y)` | 3 | 3 |
| 已展开控制 | `3*x*x-2*x*y+5*y*y` | 1 | 1 |

完成目标是等价且已展开：乘法或乘方下不能再包含待分配的加减结构；不要求合并同类项。嵌套替换仍需继续展开，所以命中规则不一定能一整题一步完成。

## 独立评分

评分器位于 [`benchmarks/knowledge_growth.py`](../benchmarks/knowledge_growth.py)，不调用生产多项式验证器。它单独解析受限 AST，计算两侧每个变量的次数上界，以 `Fraction` 精确求值，并验证完整笛卡尔网格。

若差多项式在变量 `i` 上的次数不超过 `d_i`，则在每个变量取 `d_i+1` 个不同有理数所组成的完整网格上全为零，足以推出该多项式恒为零。这依赖已经验证的多项式语法与次数上界，**不是用几个随机数值样本代替一般性证明**。

网格大小、表达式节点、深度、次数和精确数值大小均有限制。超限或不支持的语法返回 `unknown`，不会使用不完整网格宣称通过。成功要求 Agent 正常完成、残差为空、独立评分为有效且表达式已展开。未完成和技术失败保留在分母中。

## 本次结果

完整的逐题摘要见 [summary.json](evidence/knowledge-growth-v1/summary.json)。

| 指标 | 固定库 | 增长库 |
| --- | ---: | ---: |
| 独立评分成功 | 10/10 | 10/10 |
| 提案调用 / 已提交步骤 | 84 / 84 | 24 / 24 |
| 运行时恒等式检查调用 | 1,182 | 210 |
| 基础改写节点访问 | 1,686 | 383 |
| 规则匹配尝试 | 0 | 1,296 |
| 实际提交的跨题规则应用 | 0 | 8 |
| 有跨题规则应用的任务 | 0/10 | 8/10 |
| 技术错误 | 0 | 0 |

本组任务的迁移提案调用减少 **71.4%**，但成功率相同。两个控制任务没有复用规则，步骤也没有减少。命中的规则 ID、发现任务来源和指纹均保留在结果中；仅检索到了规则不算实际复用。

发现阶段另消耗 **13 次提案、110 次运行时恒等式检查**，成功完成 2/2 题并得到两条规则。知识入库调用领域验证器 2 次，重新加载再调用 2 次，迁移期间入库调用为 0。入库验证会检查整条证书；这些调用不能与单次恒等式检查混为同一单位。

上述运行时恒等式检查包含当前适配器对既有证明链的重复检查，其数量会随着推导长度增长。增长库减少这些调用，部分原因是缩短了需要重复检查的链条。规则匹配带来了额外开销，**不能据此宣称墙钟时间、总运算量、token 或费用减少了 71.4%**。没有把节点访问、匹配尝试和恒等式运算简单相加成一个“总计算量”。

另外使用独立的测试知识库进行 6 个不应入库的探针：错误展开系数、断开的推导链、无证明证书、符号除法、缺少非零条件、消去零因子。结果为 **错误入库 0/6**；其中不支持的符号除法是 `unknown`，其余被拒绝。这个有限分母不构成对任意错误规则的可靠性保证。

## 复现

直接体验保存、重载、跨题复用：

```bash
python -m resimind demo --domain knowledge-growth
```

这个简短演示从空库直接学习立方，学习成本为 16 次提案，新题两组为 16→1 次。上面的十题实验先学习平方，再用它帮助推导立方，因此总学习成本为 13 次；两个实验的分母不同。[Python API 与模型接入示例](knowledge-growth.md#use-the-python-api) · [开发回归记录](validation-knowledge-growth.md)。

在仓库根目录、安装开发依赖后运行：

```bash
python -m pip install -e '.[dev]'
python -m benchmarks.knowledge_growth --output /tmp/resimind-knowledge-growth-summary.json
python -m pytest -q tests/test_knowledge_growth_eval.py
```

默认不联网，不需要 API 密钥。JSON 输出包含全部发现和迁移任务、独立评分结果、工作计数、真正使用的规则、冻结摘要和不应入库探针；不含模型请求或私有工程素材。记录与复现结果应一致，若实现改变，应保留原结果并标明新版本。

这一轮把“验证后的推导能够积累并跨题复用”变成了可检查的代码和结果。它尚未测量神经模型能否发现困难的新规则，也没有与其他框架在相同模型、知识、任务和预算下比较。下一项能力评价应冻结任务与规则增长协议，再对真实模型进行独立的固定库和增长库实验。
